# ИИ-агенты и Unreal Engine: ландшафт, расход токенов и стратегия Healthy Unreal Stack

Дата: 2026-10-06. Статус: итог исследовательской фазы, основа для решения об архитектуре.

**Как читать.**
- Токены — оценки по прокси-токенизатору o200k, ±30% к токенизатору Claude.
- «x» — кратность к модельному «идеалу» на тех же задачах и в тех же условиях.
- Метки: **[V]** проверено по первоисточнику (код, документация, issue); **[M]** посчитано нами; **[S]** вторичный источник или сниппет поиска; **[C]** заявление вендора или проекта, не проверенное; **[I]** наш вывод.
- Ссылки вида [UTM §2.1] ведут на рабочие заметки исследования; расшифровка сокращений в §10.
- Живой Unreal Editor в исследовании **не запускался**. Все рантайм-числа — модель на общих фикстурах, а не замер.

---

## TL;DR

1. **Ответ: не форк и не ещё один MCP-сервер с нуля, а свой агентский фронт + свои тулсеты внутри реестра Epic.** На UE 5.8+ база — MCP от Epic (транспорт и 830 инструментов длинного хвоста ведёт Epic). Своё: фронт из 8 типизированных инструментов + CLI + skills и тулсеты в ToolsetRegistry — сначала Python без компиляции, потом C++ там, где Python не достаёт (AnimBP state machines, BT/StateTree, UDS, модальные окна, ≤5.7).
2. **Почему фронт.** Claude Code уже откладывает схемы MCP; лимиты жгут число запросов, большие ответы, discovery (`describe_toolset` до 62,5k токенов), скриншоты в base64 и циклы повторов. В единой модели на задачах T1–T6 Epic по умолчанию стоит **5,0x** от идеала, лучшие серверы 1,5–2,6x, лёгкий фронт **~1,0x** (0,81x с `alwaysLoad`).
3. **Почему ещё и код в редакторе.** Фронт не лечит главный реальный сток — повторы после зависаний и таймаутов (11 из 39 отчётов) — и пробелы возможностей, из-за которых агент уходит в Python-обходы (медиана 21 вызов за сессию).
4. **Не форк db-lyon** (95% коммитов от одного автора, +55k/−24k строк за 5 недель) и **не всё своё с нуля** (медиана ≈17 мес. до MVP в одиночку, дублирует то, что ведёт Epic).
5. **Первым делом (недели 1–2):** пакет конфигурации без кода (skill, CLAUDE.md, хуки Claude Code, `hus doctor`, локальный каталог Epic) и живой замер; модель обещает 5,0x → ~2x. Затем **MVP без компиляции** (~3,5 мес. вдвоём, ~7 одному); C++ — в v1 и по измеренным триггерам.
6. **До старта ответьте на три вопроса** (§9): какой клиент/сервер/режим сжёг лимиты; версия UE; доля AnimBP/StateTree/BT в работе.

## 1. Куда на самом деле уходят лимиты

### 1.1 Механика расхода

- **Каждый вызов инструмента — новый запрос со всем контекстом.** Документация Claude Code: каждый раз, когда Claude использует инструменты, уходит ещё один запрос с результатами [V costs].
  - Если базовый контекст B, а каждый из n шагов добавляет r токенов, суммарно перечитывается ≈ n·B + r·n(n−1)/2 [TE §1.2].
  - При B = 25k и r = 2k: 20 шагов дают 0,88 млн перечитанных токенов, 50 шагов — 3,7 млн, 100 шагов — 12,4 млн.
  - Если шагов вдвое меньше, квадратичная часть сокращается примерно вчетверо.
- **Кэш удешевляет перечитывание, но не обнуляет его** [V pricing, V1 claim 6]:
  - на Opus 5.5 чтение из кэша стоит 0,05x цены ввода, запись с TTL 1 час — 2x, вывод — 5x;
  - на подписке кэшированные токены, по словам Anthropic, «считаются меньше», но точный вес для лимитов не опубликован;
  - основной диалог на подписке кэшируется на 1 час;
  - документация Claude Code прямо говорит (в нашем переводе): даже короткий вопрос в сессии, открытой весь день, «расходует лимит за весь разговор»;
  - при весах API перечитывание контекста дороже свежих токенов и вывода уже при контексте ~180k на запрос (Opus 5.5).
- **Особенности Claude Code** [V mcp; EV §6]:
  - Tool search включён по умолчанию с v2.1.7 (январь 2026); сейчас по умолчанию откладываются все схемы MCP-инструментов: при старте грузятся только имена и `instructions` сервера.
  - Описания инструментов и `instructions` обрезаются на 2 048 символах.
  - Результат больше 25k токенов **или** 50 000 символов уходит в файл (#97622: порог считается в символах, а не в токенах). Модель видит только путь. Скриншот в base64 она поэтому вообще не видит.
  - `instructions` сервера тарифицируются **каждый ход**, но не видны в `/context`; в воспроизведении это 653 токена на ход (#94832).
  - `tools/call`, оборванный закрытым соединением, отправляется повторно (#98466). Неидемпотентная правка выполнится дважды.
  - `MCP_TIMEOUT` больше 60 с игнорируется (#16837).
- **Куда уходят деньги даже у идеального дизайна:** базовый контекст — 27–33%, вывод на каждый запрос — 54–64%, полезное содержимое — меньше 15% [UTM §0 п.7]. **Главный рычаг после сжатия форматов — число запросов.**

### 1.2 Шесть стоков: механизм, числа, реальные отчёты

Реальные данные: 39 отчётов (26 от пользователей UE, 6 записей агентов и логов сессий, 7 аналогов из Unity), классифицированы по главной причине [EV §3.1]. GitHub-трекеры недооценивают жалобы именно на токены: подписчики видят «лимит исчерпан», а не токены.

| Сток | Как работает | Числа (модель или замер) | Отчётов из 39 |
|---|---|---|---:|
| **Повторы после ошибок, таймаутов, обрезки Unicode** | зависание или таймаут → повтор, переделка, полное перечитывание; иногда двойная мутация | один цикл из 12 запросов при контексте 45k ≈ $0,26, то есть ≈5 типовых задач; каждый п.п. частоты циклов ≈ +5% к цене задачи [JT §2.6] | **11** |
| **Большие результаты чтения** | ответ остаётся в контексте и перечитывается на каждом следующем шаге | уровень из 2 000 акторов в «pretty JSON»: 376k токенов; TSV: 77k; обзор: **193**; запрос «51 PointLight, 4 поля» в TSV: **1 096** [TE §2.9] | 6 |
| **Определения инструментов** (клиенты без отложенной загрузки) | все схемы в каждом запросе | db-lyon 1.3.9 по умолчанию: 1 039 415 символов ≈ 297k (chars/3.5); Epic в eager-режиме: 830 инструментов ≈ 160k o200k [INV §3; EPIC §2.1] | 4 |
| **Длинные сессии и потеря кэша** | квадратичный рост; на моделях с окном 1M автокомпакция только около 967k | — | 4 |
| **Число шагов и Python-обходы** | недостающая операция превращается в цикл обходных вызовов | медиана **21** вызов `execute_python` за сессию; один экспорт — **122** круга [EV A2, A4] | 4 |
| **Скриншоты** | Epic отдаёт PNG в base64 внутри JSON-текста | **1 169 177 символов** на кадр; как image-блок 1080p стоило бы 2 691 токен, 960×540 — 700 [EPIC §2.3; TE §1.6] | 3 |
| Discovery и вес контекста (skills, CLAUDE.md) | каталоги и документация, загруженные «на всякий случай» | `describe_toolset` у Epic: Blueprint 16,1k, Sequencer 29,6k, Niagara 62,5k o200k [EPIC §2.1] | 1 + 2 |

Ещё 4 отчёта — прочее: путь оплаты, зацикливание локальной модели, сбой discovery, конфликт нескольких серверов.

Пример на уровне задачи [TE §1.9]: «найти 51 источник света из 2 000 акторов, поменять свойство, проверить».
- Дизайн «выгрузить всё и править по одному»: 62 запроса, 6,0 млн обработанных токенов, ≈$2,77.
- Дизайн «запрос + пакетная запись»: 6 запросов, 0,14 млн токенов, ≈$0,26.
- Разница — в 43 раза по токенам и в ~10 раз по деньгам (цены API Opus 5.5).

### 1.3 Другие клиенты ведут себя по-разному

| Клиент | Загрузка схем | Ограничения результатов | Что важно для нас |
|---|---|---|---|
| Claude Code | отложенная (имена + instructions), `alwaysLoad` на сервер или инструмент | 25k токенов / 50 000 символов → файл | instructions — налог на каждый ход; hooks могут переписывать вывод |
| Codex CLI | `tool_search` всегда включён; `alwaysLoad` нет | обрезка на 10k токенов | при наличии `structuredContent` модель видит только его, **картинки теряются** [V1 claim 5] |
| Gemini CLI | нет tool search: всё eager | обрезка на 40 000 символов | при входе через OAuth нет кэша промптов, поэтому важно число запросов |
| Claude Desktop / claude.ai | «Auto / Always / On demand» | — | нет shell, поэтому файлы-«спиллы» бесполезны, нужен постраничный курсор; свои skills не синхронизируются между поверхностями |
| VS Code Copilot | лимит 128 инструментов на запрос | — | — |
| Cursor | динамическая загрузка (−46,9% токенов [S]) | длинный вывод уходит в файлы [S] | — |

Правило для любого сервера: **никогда не отдавать `structuredContent`** (или делать его идентичным тексту).
- Claude Code отдаёт модели только JSON из `structuredContent` и отбрасывает текстовые блоки.
- Codex берёт только `structuredContent` и теряет картинки.
- Gemini берёт только `content` [V1 claim 5].

### 1.4 Что можно сделать уже сегодня, без нашего кода

- **Режимы-шлюзы в Claude Code обычно вредят.** В Claude Code схемы и так откладываются, поэтому search → describe → execute только добавляет круги. ChiR24 0.6 (шлюз) дороже своей же 0.5.30 в 1,5–2,6 раза; профиль `search` у ZiggyMar — до 1,8x от `full`; режим `micro` у db-lyon (HEAD) хуже `full` из npm 1.3.9 на 5 из 6 задач [UTM §2.5].
- **Epic 5.8:**
  - не вызывайте `CaptureViewport` через `call_tool`, чтобы «посмотреть»: это мегабайты base64;
  - не запускайте `describe_toolset` для больших тулсетов;
  - отключите «Use Less CPU when in Background»: ~333 мс против 8 мс на команду [UEI §6].
- **Гигиена сессий:**
  - `/clear` между задачами;
  - `/autocompact` на 300–500k на моделях с окном 1M;
  - «On demand» для инструментов в приложениях Claude;
  - не пускайте Claude Code через LLM-шлюз (`ANTHROPIC_BASE_URL`): за ним отключается tool search, а снятые маркеры `cache_control` превращают всю историю в некэшированный ввод [TE §1.4];
  - смотрите `/usage`: там есть разбивка по MCP-серверам и строка попаданий в кэш.

## 2. Что уже существует

### 2.1 Epic Unreal MCP (UE 5.8, Experimental) — новая реальность 2026 года

**Что это** [BRIEF §1; EPIC §1]:
- Плагины `ModelContextProtocol` + `ToolsetRegistry` + ~27 тулсет-плагинов (агрегатор `AllToolsets`).
- Streamable HTTP на `127.0.0.1:8000/mcp`. Аутентификации нет: только loopback и проверка Origin.
- Генератор клиентских конфигов для Claude Code, Cursor, VS Code, Gemini, Codex.

**Режим по умолчанию — «tool search».**
- В `tools/list` всего 3 мета-инструмента: `list_toolsets`, `describe_toolset`, `call_tool`, ≈0,28k o200k.
- В мае 2026 Epic отказался от подгрузки инструментов посреди сессии в пользу статического `call_tool`, «чтобы кэш промпта оставался тёплым» (коммит в MIT-плагине Epic).
- Каталог: **52 тулсета / 830 инструментов**, без изменений с 5.8.0 по 5.8.3. Если выставить всё плоско (eager), это ≈205k токенов по chars/3.5.

**Discovery дорогое** [EPIC §2.1; V1 claim 3]:
- `list_toolsets` — 12 988 символов (≈2,7k o200k).
- `describe_toolset`: медиана ≈9 тыс. символов (≈2,6k по chars/3.5); BlueprintTools 16,1k, SequencerTools 29,6k, NiagaraToolset_System 62,5k токенов o200k.
- `outputSchema` занимает 37,6% байтов.
- 6 из 52 описаний длиннее 50 000 символов, поэтому в Claude Code они уходят в файл и стоят дополнительных кругов.

**Изображения.** Все 4 инструмента захвата отдают полноразмерный PNG в base64 **внутри JSON-текста**, никогда не MCP image-блоком. Наблюдалось 1 169 177 символов на кадр.

**`execute_tool_script`** (пакет вызовов за один круг) [V2 claim 2]:
- песочница без модуля `unreal`;
- импорт ограничен `json/math/datetime/copy/re/time`;
- ответ закодирован дважды внутри `returnValue` (+15%);
- при ошибке есть настоящий undo, **но не «всё или ничего»**: созданные ассеты остаются, нетранзакционные записи не откатываются, а сам откат может уронить редактор, если редактор этого ассета открыт.

**Надёжность** [EPIC §1 4c]:
- всё выполняется на game thread;
- серверного таймаута нет, `cancel` ничего не делает;
- модальное окно замораживает весь сервер;
- синхронные инструменты выполняются строго последовательно.

**Задокументированные причуды** [S, полевые заметки]:
- `find_actors`, по сообщениям, молча обрезает выдачу на 20 строках;
- `set_properties` не вызывает `PostEditChange` и не помечает пакет изменённым;
- `TOptional`-параметры нужно передавать явным `null`.

**Хорошие идеи внутри:**
- Blueprint DSL на S-выражениях в обе стороны. Оговорка: представление с потерями и с известными сбоями при записи [V2 claim 5].
- Чтение подграфов (`find_nodes`, `get_connected_subgraph`).
- `execute_tool_script`.
- Agent Skills, зарегистрированные в проекте.
- `LiveCodingToolset` и `AIAssistant` (`GetDockedContext`) как opt-in плагины.

**Python в 5.8.** Появились `unreal.BlueprintGraphEditor` и `BlueprintGraphPinLibrary`: Python теперь создаёт K2-ноды и соединяет пины.
- На ≤5.6 это **проверенно невозможно**, по 5.7 данных нет.
- Ловушка локализации: `create_node_from_name` требует **локализованные** имена, и на итальянском редакторе он ломается. Русский UI — ровно этот случай. Типизированные хелперы (`add_branch_node`, `add_call_function_node`) эту проблему обходят [V2 claim 1].

**Точки расширения:**
- C++: `UToolsetDefinition` + `UFUNCTION(meta=(AICallable))`;
- Python: `@toolset_registry.tool_call`, регистрация из `init_unreal.py`.

Скилл Epic `create-toolset` (MIT) прямо говорит: «Python is generally preferred» [JF §2.4].

**Дорожная карта** [S]:
- 5.9 подтверждена на Unreal Fest Seoul (2026-08-20): «больше MCP-skills», EDA с контекстом проекта.
- UE6 Early Access — конец 2027, «построен вокруг MCP» с Claude/Gemini/Codex.
- UEFN использует тот же MCP с 2026-08-20: 29 тулсетов / 384 инструмента.
- Внутренняя «вкладка Claude Code», пристыкованная к редакторам ассетов, есть в текстах Epic, но **не в публичных сборках 5.8** [V2 claim 3].
- Официальный плагин Epic для Claude Code (MIT) лежит в официальном маркетплейсе Anthropic.

### 2.2 NeoStack AI (Betide Studio, бывший Agent Integration Kit) — закрытый конкурент

**Источники — только публичные материалы:** документация, changelog и страница Fab вендора, официальный репозиторий `betidestu/neostack-plugins` и сторонний мост `Dqz00116/AIKAgentBridge` [S/C]. По ходу исследования агенты наткнулись на копии самого плагина в чужих игровых репозиториях. Это, скорее всего, несанкционированное распространение платного продукта, поэтому выводы из этих копий в документ **не включены**, а ссылки на них не приводятся (принцип «чистой комнаты», §8.1).
- **Code mode.** По документации вендора агенту дан **один компактный инструмент исполнения**: агент пишет Lua-скрипты против API редактора NeoStack вместо того, чтобы держать в контексте сотни определений инструментов. Цикл правки: `create_asset → open_asset → info → list → add/configure/remove → compile/save/validate` [S].
- **Профили** (5 встроенных) — белые списки категорий инструментов, видимых агенту [S].
- **Охват.** Вендор заявляет около 60 интеграций с движком: Blueprints, AnimBP, материалы, Niagara, Sequencer, BT/StateTree, PCG, IK, MetaSounds, Enhanced Input, Motion Matching, DataTables и другие [C].
- MCP-эндпоинт в редакторе на `localhost:9315`, по данным стороннего моста AIKAgentBridge [C].

**Хостинг** (документация вендора [S]; HOST §6):
- «Agent Chat» в редакторе — ACP-клиент. Claude Code он запускает через адаптер `claude-agent-acp` на подписке пользователя; также Codex, Gemini CLI, Cursor, Copilot CLI.
- Свой агентский цикл через OpenRouter/Ollama.
- NeoStack Cloud: $20 за место в месяц.
- Stdio-прокси для Rider и других MCP-клиентов: официальный `neostack-connect` (Go, MIT) [V].
- Индекс проекта и skills.

**Заявления вендора, не проверяемые** [S/C]:
- «простая операция над BP: 40–50k → ~4k токенов» (v1.0, март 2026);
- вендорский бенчмарк: NeoStack 3/5 задач за 145 запросов против Epic 1/5 за 375. Один прогон на задачу; сам вендор называет это «направленным свидетельством»;
- цена $109.99 разово на Fab; UE 5.5–5.8; рейтинг 4.4★.

**Риск модели хостинга.** Вход по подписке Claude через ACP-хост стороннего продукта требует предварительного одобрения Anthropic. Свидетельств такого одобрения мы не нашли [HOST §2].

### 2.5 Уроки Unity и Godot [COM §5]

**Что сделали лидеры:**
- **CoplayDev unity-mcp:** 49 инструментов ≈ 29,1k токенов + 1,5k instructions.
  - Группы инструментов переключаются посреди сессии, а это ломает кэш.
  - `batch_execute` до 100 команд.
  - Чтения идут через ID и MCP-ресурсы.
  - Правки — по якорю или хэшу (`precondition_sha256`), без пересылки целых файлов.
- **Официальный Unity MCP:** relay-бинарник + статические методы с атрибутом `[McpTool]`. Это та же схема, что реестр Epic.
- **godot-ai:** 47 инструментов ≈ 28,5k, из них 43 с `defer_loading`; eager остаются только 4 «core» ≈ 1,4k; `batch_execute` с откатом.
- **better-godot-mcp:** 17 составных инструментов + `help`.
- **GDAI:** цикл «ошибка → патч → запуск → проверка скриншотом».

**Выводы:**
- мало видимых инструментов;
- пакеты или код вместо цепочек вызовов;
- ID вместо дампов;
- правки по якорю;
- индекс проекта как платная фича;
- петли проверки;
- **пользователи ненавидят непрозрачные кредиты** (ветки Unity Discussions про «кредиты сгорели за 10 минут»).

### 5.1 Стратегии кратко

- **A «Надстройка»** — фронт `hus` поверх MCP Epic и Python Remote Execution, без своего плагина в редакторе.
  - Для ≤5.7 опирается на Claireon.
  - Пакет конфигурации — на 2-й неделе; Python-тулсеты — только в v1.
- **B «Форк»** — мягкий форк db-lyon/ue-mcp (C++-плагин) + свой фронт + свой C++-модуль + порты доноров.
- **C «Своё с нуля»** — свой C++-рантайм, свой транспорт с фреймингом, фронт на Go; code mode — первая сущность; UE 5.5–5.8.
- **D «Epic-native гибрид»** — свой фронт + свои C++-тулсеты в ToolsetRegistry Epic + тонкий мост для ≤5.7 и side channel + док-панель.

  - **Вес core-skill.** Если он грузится раз за разговор: A 1,30x, D 1,36x, B 1,52x, C 1,53x.
  - **Длинный хвост.** При 30% задач вне T1–T6 стоимость *успешной* задачи в MVP: B 1,21x, C 1,31x, D 1,44x, A 1,60x; у A, C и D 10% задач невыполнимы. В v1: C 0,86x, D 0,86x, B 1,02x, A 1,46x.
  - **T8 (многотиковая проверка в PIE).** Как спроектированы: A 3,41x, B 3,31x от C. Любой фронт со step runner делает T8 за ~3,1 запроса (1,15x от C «холодно», 0,82x «тепло»). Отрыв C — решение в API, а не стратегия.
  - **Циклы сбоев.** +1 п.п. их частоты весит больше, чем весь разброс между фронтами на T1–T6.

### 5.5 Где судьи сошлись

Все три независимо пришли к одной **конечной форме: свой фронт + свои тулсеты внутри ToolsetRegistry Epic.** Расходятся они только в том, *когда начинать C++*:
- **Токены:** C++-ядро и порты доноров для «трудных» доменов уже в MVP, чтобы ничего не было невыполнимым.
- **Осуществимость:** MVP без компиляции на Python-тулсетах; C++ — только по измеренным триггерам.
- **Продукт:** MVP без компиляции; C++ для AnimBP/BT/StateTree/UDS — по графику в v1, потому что без них проект не альтернатива NeoStack.

Наша рекомендация ниже примиряет это так:
- MVP без компиляции;
- C++ для «трудных» доменов — по графику в v1, но с переносом в MVP, если они составляют заметную долю работы пользователя;
- C++ для надёжности — по замеру;
- ≤5.7 — по триггеру.

## 6. Рекомендация

### 6.1 Решение

Строим **Healthy Unreal Stack** как **агентский слой поверх платформы Epic**. Это не параллельный сервер, не форк и не чат-приложение.
1. **Фронт `hus`** — единственное место, где экономятся токены. Работает в любом клиенте.
2. **Тулсеты, зарегистрированные в ToolsetRegistry Epic**, исправляют то, что фронт исправить не может. Их видят все агентские поверхности Epic.
3. **C++ появляется** только там, где Python бессилен (авторинг AnimBP/BT/StateTree/UDS, side channel, ≤5.7), и только по графику или измеренному триггеру.
4. **Если Epic что-то поглотит, мы удаляем свой код, а не устареваем.**

Позиционирование для README: *«Бесплатный открытый агентский слой для Unreal, который считает токены: делает MCP от Epic доступным по цене и надёжным для агентов, добавляет авторинг, которого нет у Epic и OSS, и работает из того агента, за которого вы уже платите».*

### 6.5 Правила результатов и формат графов

**Результаты:**
- TSV с одной строкой заголовка и короткими handles (`h3`, `n12`, `u7`) вместо GUID и путей.
- Числа округлены, значения по умолчанию опущены.
- Бюджет по умолчанию — 4k токенов на ответ, с поправкой на кириллицу: в TSV с метками ≈1,7 символа на токен против 2,1 для латиницы [UTM §3].
- Профиль Codex — ≤6k (его обрезка — 10k).
- Переполнение уходит в файл `Saved/hus/results/<id>.tsv` с 5 строками начала и подсказкой «сузьте через …». Для клиентов без файлов (Claude Desktop, определяем по `clientInfo`) — постраничный курсор.
- Картинки — только image-блоками.
- **Никогда не `structuredContent`.**
- Ошибки — как результат `isError`, ≤600 символов: `{code, fix, next, closest}` с точным следующим вызовом.
- Подтверждения записи — однострочные диффы (24 токена против 204 у полного JSON объекта [TE §2.9]).

**Графы:**
- Вид по умолчанию `dsl` — S-выражения с member-ссылками и id на каждой ноде (≈943 токена на 80 нод).
- Перед патчем — `edges` по окрестности (полный граф — 1 362 токена).
- Патчи построчные: `+n90 Branch`, `n12.ReturnValue -> n90.Condition`, `@after n0: n90 n91`. Каждую строку можно проверить отдельно, ошибка указывает на строку.
- Ноды создаём по классу и member-ссылке, **никогда по локализованному имени** (русский UI).
- JSON остаётся за флагом.
- **Формат по умолчанию утверждаем только после eval** на Sonnet и Opus: DSL против рёбер против JSON, метрика — токены на успешную задачу. Опубликованных данных о том, как Claude пишет graph DSL, нет, а у DSL Epic есть задокументированные сбои при записи [V2 claim 5].

### 6.8 Хостинг в редакторе в рамках правил подписки Anthropic

| Режим | Что это | Делаем? |
|---|---|---|

### 7.3 Метрики успеха и критерии остановки

**Публичные KPI:**
- **токены на успешную задачу** (главная метрика) на T1–T8 и хвосте против Epic по умолчанию и L0;
- запросы на задачу;
- успех, проверенный по состоянию редактора, а не по словам агента;
- инциденты на 100 мутирующих вызовов; двойные мутации = 0;
- простой game thread в мс;
- время до первого успеха;
- индекс паритета;
- внешние контрибьюторы: ≥5 PR от ≥3 человек за 3 месяца после MVP;
- доля не-Claude клиентов.

**Критерии остановки и разворота:**
- **K1.** Гейт фазы 0 не пройден → перемерить, прежде чем писать фронт.
- **Спайк Python-тулсетов не прошёл** → маршруты через Python Remote Execution (вариант A).
- **K4.** Код в редакторе не вдвое снижает инциденты против `--toolsets=off` (это и есть архитектура A, на том же стенде) → заморозить C++ надёжности. Авторинг «трудных» доменов остаётся: он нужен ради возможностей, а не метрик.
- **K6.** DSL или TSV теряют >5 п.п. успеха против JSON на Sonnet/Opus → сменить форматы по умолчанию.
- **Меньше 3 внешних контрибьюторов** через 6 месяцев после MVP → сузиться до фронта и skills, «трудные» домены — через доноров и апстрим (например, в VibeUE).

### 8.2 Правила подписки Anthropic: что может и чего не может OSS-хост в редакторе

Первоисточники прочитаны 2026-10-06 [HOST §2; V2 claim 4].

**Можно:**
- Конечный пользователь входит в **немодифицированный бинарник Claude Code** со своей подпиской, «в том числе когда платформа хостит Claude Code» (здесь и ниже — наш перевод).
- Отсюда разрешены (a) официальный клиент + наши инструменты и (b1) терминал в редакторе с интерактивным `claude` пользователя.

**Нельзя:**
- Предлагать вход через claude.ai в собственном приложении.
- Направлять запросы через учётные данные Free/Pro/Max от имени пользователей.
- Собирать, хранить или проксировать учётные данные claude.ai.
- Модифицировать бинарник или отключать его методы аутентификации.

**Agent SDK:** «если нет предварительного одобрения, сторонним разработчикам нельзя предлагать вход claude.ai или лимиты подписки для своих продуктов». Сюда относятся `claude -p` и ACP-адаптер `claude-agent-acp`.

**Статус оплаты на июнь 2026.** План перевести Agent SDK, `claude -p` и сторонние приложения на отдельный кредит поставлен на паузу 2026-06-15. Сейчас они ещё расходуют лимиты подписки; по нашей оценке, именно этот класс первым попадёт под новые правила [I]. Документация уже объявила, что `--bare` (без OAuth) станет умолчанием для `-p`.

**Итог для нас:**
- (a) и (b1) — да;
- (b2) панель с `claude -p` — нет;
- (c) ACP с подпиской Claude — только с одобрением Anthropic, иначе по API-ключу или для других вендоров;
- (d) свой цикл — только API-ключ.

Бенчмарки в CI гоняем по API-ключам.

## 10. Методология и оговорки

**Как получены числа.**
- **Живого редактора не было.** Все числа получены из кода, сохранённых ответов серверов, проб третьих лиц, клонов репозиториев и моделей.
- **Модель стоимости** [UTM §1]: каждый запрос перечитывает контекст.
  - Ранее отправленный префикс — чтение кэша, всё добавленное — запись в кэш с TTL 1 ч.
  - Цены API Opus 5.5: ввод $4, запись 1 ч $8, чтение кэша $0,20, вывод $20 за 1 млн токенов.
  - База 20k токенов; 300 токенов вывода на запрос.
  - Потоки запросов — реконструкции [I] по документации каждого сервера; реальные агенты пропускают или повторяют шаги.
  - Движок воспроизводит более ранние модели исследования точно.
- **Подписка.** Цены API — только прокси для лимитов подписки: вес кэшированного чтения для лимитов Anthropic не публикует. Чувствительность с весом 1,0 ранжирование не меняет, меняет только масштаб.

**Токены.**
- Основная единица — o200k, ±30% к Claude.
- Оценка chars/3.5 **завышает** определения и прозу на 10–28% и **занижает** числовые результаты на 15–65% [UTM §1.1].
- Токенизатор Claude 4.7+ даёт ~1,0–1,35x токенов относительно старых.
- Абсолютные числа менее надёжны, чем отношения между конфигурациями.

**Частоты.** Частоты сбоев и циклов (2/4/5/10% на задачу), доля хвоста (10/30/50%) и равное деление хвоста — допущения [I]. Таблицы показывают масштаб и чувствительность, а не прогноз.

**Модели сроков и паритета** — структурированная проверка здравого смысла, а не прогноз [JF §1; JP §2.2].

**Выборки.** 39 отчётов о потерях — показательные, не статистика. GitHub недооценивает жалобы на токены. Комментарии к issues не читались; Reddit, Discord и Fab были недоступны.

**Заявления вендоров [S/C], не проверенные:**
- NeoStack: 40–50k → 4k, бенчмарк 3/5 против 1/5, цена и рейтинг;
- Ludus: «в 6 раз дешевле»;
- StraySpark: 17 КБ против 300 КБ;
- Coplay: «10–100x»;
- Cursor: −46,9%;
- цифры «до/после» самих OSS-проектов.

**Применённые поправки:**
- 126k → 3,1k у ZiggyMar — урезанный вид (§2.4);
- 1,04 млн символов у db-lyon — только npm 1.3.9;
- `list_toolsets` ≈2,7k o200k (3,7k по chars/3.5), а не 4,1k;
- откат `execute_tool_script` частичный;
- точность DSL на Sonnet/Opus **не доказана**.

**Сокращения рабочих заметок.** Заметки внутренние и в репозиторий не входят: часть из них цитирует исходный код Epic и опирается на копии сторонних продуктов, которые нельзя использовать как источник (§8.1). Ссылки на них ниже нужны только для прослеживаемости.
